# v1.3.1 — Official Public API primary + optional MyŠkoda Login (MyŠkoda)

**Status:** design approved 2026-10-20  
**Release:** `v1.3.1` on `main` after merge queue  
**Live evidence:** `_local_docs/notes/bff_vs_public_api_comparison.md` (same-car snapshot parity + mint proof)

---

## [S1] Problem

v1.3.0 dual-stacks official Public API with the old unofficial `myskoda` library (legacy). That legacy path is brittle (MQTT/REST may die without notice), already has weaker commands (heat/enable paths were incomplete), and confuses product story.

MyŠkoda Login unlocks extra remote commands and key creation.

Users need a clear story:

1. **Default / primary:** official **MyŠkoda Public API** (their own key) — supported, stable, rate-limited 20/h/VIN.
2. **Optional advanced:** **MyŠkoda Login** (username + password) — more remote control and status, private-API caveats.
3. **Remove** the old `myskoda` library as a telemetry source.

---

## [S2] Solution overview

Two `VehicleSourcePort` implementations only:

| Source | Auth | Role |
|---|---|---|
| **PublicSource** | `X-API-Key` (user key or minted) | Default telemetry + charge/AC commands |
| **LoginSource (MyŠkoda)** | Škoda ID password → Bearer (`login token`) | When connected: **wins** for telemetry + full commands |

- **Auto:** Login if saved → else Public if key → else “Connect a source” error.
- Per-vehicle `telemetry_source` ∈ `auto` | `public` | `login`.
- **Drop** legacy `myskoda` imports, MQTT legacy wake, and using `ConnectorSession` password as a *telemetry* source.
- **Auto-mint helper:** Login → `POST /api/v2/public-api-keys` → store encrypted official key (onboarding / fallback when Login is off).

Naming in UI: **Auto · MyŠkoda Public API · MyŠkoda Login**.

## [S3] Source selection and data flow

```text
collect_vehicle / command
        │
        ▼
VehicleSourcePort.fetch_snapshot(vin) / command(op)
        │
        ├── LoginSource   (MyŠkoda)     ← preferred when credentials exist
        └── PublicSource  (X-API-Key)
        │
        ▼
skoda_normalize.snapshot_from_public | snapshot_from_bff
        │
        ▼
NormalizedSnapshot → existing telemetry tables
```

### [S3.1] Auto policy

1. If Login credentials exist for the user (and vehicle not forced `public`): use **LoginSource**.
2. Else if `skoda_public_api_key_encrypted` valid: **PublicSource**.
3. Else: skip collect with user-facing setup CTA (not a silent fail).
4. On Login auth failure: fall back to Public once per cycle if key present; surface re-login error; do **not** delete the Public key.
5. On Public 401 expired / 429: human error via existing `friendly_skoda_error`; stretch interval (already implemented).

### [S3.2] One primary fetch per cycle

- **Public:** 1 composite `GET /api/v1/vehicles/{vin}?include=info,status,charging,odometer,parkingPosition,airConditioning,fuelStatus,operations`.
- **Login:** minimum set per cycle — `GET api/v1/charging/{vin}`, `api/v2/vehicle-status/{vin}`, `api/v3/maps/positions/vehicles/{vin}/parking` (and `/driving-range` only if charging omits SoC). Extra MyŠkoda reads (maintenance, readiness, battery-health) at **low frequency** (e.g. 1/hour or on Active start), not every parked tick.

## [S4] Telemetry field mapping

`NormalizedSnapshot` stays the single writer contract. Add `snapshot_from_bff(...)` mapping:

| Snapshot field | Public | MyŠkoda Login |
|---|---|---|
| `soc` | `charging.status.battery.stateOfChargeInPercent` | `charging.status.battery` or driving-range |
| `remaining_range_m` / `range_km` | battery / fuelStatus | charging + driving-range |
| `charge_power_kw`, `charge_state`, `charge_type`, `plug_connected`, `target_soc` | `charging.*` | `charging.*` (+ AC chargerConnectionState if needed) |
| `odometer_km` | `odometer.mileageInKm` | maintenance report / vehicle data |
| `lat`/`lon`, `is_parked`, `is_moving` | `parkingPosition` | maps parking + readiness `inMotion` |
| `hvac_state`, `hvac_setpoint_c` | `airConditioning` | `air-conditioning` |
| doors/lock/windows (optional VehicleStatus rows) | `status.overall`/`detail` | `vehicle-status` overall/detail |
| `is_online` | payload present | readiness `unreachable=false` preferred |

**Do not** invent fields Public already has by calling extra MyŠkoda endpoints every cycle (quota/latency).

## [S5] Commands and capabilities

Router order: **Login if present → else Public → else disabled control + explanation.**

| Capability | Login MyŠkoda | Public API |
|---|---|---|
| Charge start/stop, set limit, set mode | ✅ | ✅ POST `/vehicles/{vin}/charging/...` |
| Climate start/stop, target temp | ✅ | ✅ `airConditioning/...` |
| Window heat / seat heat / aux heat / ventilation | ✅ | only if `operations[]` lists them |
| **Wake** | `POST api/v1/vehicle-wakeup/{vin}` | ❌ |
| Lock / unlock / honk-and-flash | `vehicle-access` | ❌ |

UI: hide or disable wake/lock when only Public is connected, with copy: “Connect MyŠkoda Login for wake and lock.”

Implement MyŠkoda client methods for the full set the app RE supports that product needs for v1.3.1: charge start/stop/limit, climate start/stop/setpoint, window heat, **wake**, lock/unlock. (Aux heat / camping / profiles can follow in 1.3.x if time-boxed out.)

SPIN: if MyŠkoda commands require SPIN verify (`api/v1/spin/verify`), surface a human prompt once; do not fail silently.

## [S6] Auth (MyŠkoda Login)

Port of proven lab flow (`/tmp/skoda-bff-lab/login_probe.py` + ioBroker skodae):

1. secure login S256 authorize: `(app client)`, `redirect_uri=myskoda://redirect/login/`, scope per MyŠkoda 8.x.
2. MyŠkoda sign-in `signin-service` identifier + authenticate (cookie jar).
3. `POST https://MyŠkoda API/api/v1/authentication/exchange-authorization-code?login token` body `{code, redirectUri, verifier}`.
4. Store `accessToken`, `refreshToken` encrypted (`crypto.encrypt_field`). Refresh via `.../refresh-token?login token`.
5. User-Agent: MyŠkoda Android app UA. No LLM branding in minted key names (`name: "iVDrive"`).

**Security:** password stored encrypted for silent re-login if refresh dies; document that Login is **MyŠkoda Login**. Never log tokens/passwords. No secrets in git.

## [S7] Auto-mint official keys

When Login is connected and user has **no** Public key (or key expired):

- Optional Settings button **“Create official API key”** and/or auto-mint once on Login connect (product default: **auto-mint on first successful Login connect** if no key).
- `GET /api/v2/public-api-keys` → if `keysRemaining > 0`: `POST {name: "iVDrive", vin}` → secret once → store `skoda_public_api_key_encrypted` + `skoda_public_key_expires_at` from `validUntil`.
- Cap: 5 keys/VIN. If `keysRemaining == 0`, tell user to delete one in MyŠkoda app or paste a key.
- Deleting Login does **not** delete the minted key (Public keeps working).
- Expiry copy: warn ≤14 days; observed lifetime often **~6 months** — say “several months” / show exact `validUntil` date.

## [S9] Errors (human language)

Reuse / extend `friendly_skoda_error` and user_messages:

- Invalid MyŠkoda password / account locked → re-enter credentials.
- Login session expired → “Session expired — reconnect MyŠkoda Login” + auto-attempt refresh then silent re-login once.
- API key expired / unauthorized / rate limit → existing messages.
- Command unsupported on Public → “Connect MyŠkoda Login for this action.”
- Never show raw problem+json URIs or only HTTP codes.

## [S13] Success criteria

1. New user can run **only** with official API key (paste or minted) and get full trips/charging analytics as today.  
2. User who adds **MyŠkoda Login** gets wake, lock/unlock, climate/heat commands that work (superseding old beta gaps).  
3. No `myskoda` library in the production telemetry path.  
4. UI source names are **Auto · MyŠkoda Public API · MyŠkoda Login**.  
5. Secrets encrypted; no keys/passwords in git; human errors everywhere.  
6. `v1.3.1` tagged after merge; CHANGELOG + announcement.
